# 动作工作台

独立的 HY-Motion 1.0 本地工具。复用项目依赖，但有单独的页面、开发服务与素材目录，不加载项目聊天、场景或正式动作配置。

```sh
cd motion-workbench
npm run dev
```

依赖复用项目根目录的 `node_modules`，首次使用时在项目根目录运行 `npm install`。也可以从项目根目录启动：

```sh
npm run motion
```

打开 http://127.0.0.1:5680 。项目原本的 `npm run dev` 不受影响。

## 操作

1. 点击动作库的 **＋**，填写名称、动作描述和时长。也可以直接导入 FBX。
   尚未选择动作时可以点击 **载入免费演示动作**，用随工具提供的自制骨架练习编辑与导出，不调用腾讯云。
2. **生成新版本** 会保存当前描述，并调用 HY-Motion 1.0。每次点击生成会消耗腾讯云积分；工作台不会自动重试提交。只允许一个生成任务同时进行。
3. 从版本记录中选择候选，播放、拖动时间轴，调整起止时间、速度、水平位移、地面基准和骨骼角度。
4. **保存为新版本** 留下新的编辑记录，旧版本与原始 FBX 保留。切回旧版本可重新分支迭代。
5. 默认使用有蒙皮的素体预览。可切换 **夏夏 · 项目角色**、原始动作、示例 VRM，或载入本地 `.vrm` 替换角色；切换时保留同一时间点。模型与动作加载期间显示 Loading，禁用工作台操作和镜头交互，加载失败会解除锁定并显示原因。视图支持鼠标拖动旋转、滚轮缩放。点击预览区域或用 Tab 聚焦后，方向键 / WASD 控制上下左右平移；按住连续移动，失焦立即停止，不影响输入框编辑。镜头自动适配全身，骨架叠层默认关闭，可按需打开。骨骼角度为原始 FBX 骨骼的局部轴，VRM 预览会换算，各视图效果一致。这里延续项目旧的 SMPL-H 重定向方法；拖动微调用 IK 求解姿态，没有关节角度限制或碰撞求解。
6. 满意后标记当前版本成熟。新生成或新保存调整会重置成熟标记，确保新候选重新检查。可在任意角色预览下直接导出当前调整的 **GLB**，无需先保存；保存版本后可导出 **编辑记录 JSON**，也可下载原始 **FBX**。工具不写入正式项目的动作配置；GLB 是通用骨骼动画，接入 VRM 时仍需重定向。
7. 删除动作会将所有版本移到回收站，点击回收站中的动作可恢复。生成中不能删除。

## 按反馈迭代下一版

HY-Motion 只接受文字，不能拿上一版动作当输入，所以“基于上一版”指的是：描述在上一版的基础上按反馈修改，调整参数则直接沿用。

1. 选中一个已完成的版本，播放审阅，需要时先做裁剪、速度和骨骼微调。
2. 在 **下一轮迭代** 写下这一版哪里不对，例如“挥手太快，手只抬到胸口”。
3. 点击 **✦ AI 按反馈改写描述**：DeepSeek 以上一版描述为底稿，只改反馈涉及的部分，并参考这条版本链上之前几轮的反馈，避免把已经修好的问题改回去。结果包含新描述、动作细节、关键姿态和“改了什么”的说明。未配置 DeepSeek 或者是导入版本时，可以选 **手动改写描述**。
   默认勾选 **附带截图给 AI**。点击时会从预览自动截两张图发给 DeepSeek 识图：一张是当前帧（600×800），一张是整段动作均匀取样的 8 帧拼图（每格 300×400，标注序号和秒数）。镜头沿用你当前的观察方向，自动对准全身并覆盖整段动作的活动范围；截图时隐藏关节点和骨架线，画面里是当前预览角色和你当前的调整。所以先把视角转到能看清问题的方向，停在出问题的那一帧，再点改写。AI 会在“改了什么”里说明它从图里看到的问题，确认页可以展开“AI 看到的截图”核对。两张图合计约 2000 图像 token，按 DeepSeek 计费；`DEEPSEEK_MODEL` 必须是支持图片输入的模型（默认的 `deepseek-flash` 支持）。
4. 核对新旧描述后点击 **确认生成下一版**，这时才会提交生成并消耗积分。描述保存到动作上；新版本记录父版本和本轮反馈，默认沿用当前的裁剪、速度和骨骼微调（包括未保存的调整），可以取消勾选。
5. 生成完成后弹出提示；如果你还在这个动作上且没有未保存的调整，会自动打开新版本，接着从第 1 步开始审阅。

选中任何有父版本的版本时，右侧 **与上一版对比** 会列出两版的差别：生成描述的逐字差异（新增的字标绿，删掉的字划线）、本轮反馈、动作细节有没有改，以及时长、扩写、裁剪、速度、循环、水平锁定、地面校正中改动过的项（没改的项折叠成一行），还有每根骨骼的新增、移除或调整量（例如“左手腕 旋转 X +12°”）。点击骨骼条目会在微调面板中选中这根骨骼。如果当前有未保存的调整，就拿当前调整和上一版比较。

版本记录里，这类版本显示为“迭代生成 ← 父版本”，悬停可看到反馈；“生成描述与参数”里也会显示本轮反馈。只做编辑调整的版本会并入它来源的那一轮，不算新的一轮。

## AI 补充描述

填写简短动作意图后，点击描述旁的 **✦ AI 补充**，使用项目 `.env.local` 中的 `DEEPSEEK_API_KEY` 调用 DeepSeek。可选 `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL`，默认 `https://api.deepseek.com` / `deepseek-flash`。

AI 根据当前描述、时长与已有细节，补充重心、肩肘腕、手掌方向、腿脚触地、动作节奏和收势，并给出起始、过渡、峰值与结束等关键姿态及秒数。结果包含：

- **生成描述**：不超过 128 字，发给 HY-Motion。
- **动作细节与关键姿态**：完整的时间节点与姿态描述，保留作为迭代参考，可继续编辑；随动作保存，并在新生成/导入版本里留档。

补充结果先放入可编辑草稿，不自动保存或生成动作。**撤销 AI 补充** 能还原调用前的描述与细节。HY-Motion 的文生动作接口只接受生成描述，关键姿态参考不会变成逐帧硬约束。每次点击 AI 补充产生 DeepSeek API 用量；不自动重试或调用动作生成。

## 预览模型

- **素体**：直接读取本地已有的 `public/models/candidates/VRoid_V110_Female.vrm`（主项目隐藏的“素 · 灰色素体”），作为默认动作预览，不复制或修改模型。它位于 gitignored 目录，换机器时需要放回同一路径。
- **夏夏**：直接读取正式项目已有的 `public/models/AvatarSample_A.vrm`。

素体的来源与授权差异见主项目 README 的模型说明：作者 README 允许商用和再分发，文件元数据却禁止再分发。这里沿用本地文件作预览，保留原始元数据。原 Quaternius 素体与来源记录仍保存在 `motion-workbench/models/`，已不作为默认预览。

## 骨骼微调

左右手各提供五指、每指三节，共 30 个手指关节；按当前模型实际存在的骨骼启用选项。原有角度参数和编辑版本继续保留。

预览上方的「显示骨架」「圆环微调」「拖动微调」三个勾选项互斥，也可全部关闭。选中任一微调方式后，右侧微调参数展开，播放暂停，模型显示可点击的关节点。点击关节或使用下拉列表选择骨骼。手指较小时可滚轮放大模型。

- **圆环微调**：拖动彩色圆环，只旋转选中的这一根骨骼。
- **拖动微调**（IK）：按住关节点拖到目标位置，上游的一段骨骼链一起旋转让关节跟随鼠标，骨长不变，不会拉伸变形。拖动期间，被联动的关节点高亮。
  - 手腕 / 脚踝：两骨 IK 带动上臂+前臂 / 大腿+小腿，肘、膝沿原本的弯曲方向折叠，手掌、脚掌保持原朝向；够不到时肢体伸直，不拉长。
  - 肘 / 膝 / 肩 / 锁骨 / 脚尖 / 手指：旋转上一节（指尖带动两节）。
  - 胸、颈、头：带动脊柱 2~3 节，弯曲分摊到各节。
  - 骨盆、腰、胯：移动整个身体重心，双腿 IK 让脚踝留在原地，往下拖就是下蹲。开启「锁定水平位移」时，只有上下拖动有效果。

拖动结果都写成旋转偏移（骨盆另有重心位置），面板数值会同步，可以继续手动修改。「清除全部骨骼微调」可以一键撤掉所有拖动结果。

偏移统一按原始 FBX 骨骼的局部轴保存，也就是 GLB 导出所用的骨骼轴。VRM 预览时按重定向公式换算到规范化骨骼，因此素体、VRM 角色、原始动作和导出 GLB 的姿势一致。以前在 VRM 视图里用圆环调过的版本，现在在 VRM 中的显示会改为与导出一致。旧版本里非骨盆关节的位置偏移仍然生效并可修改或重置，但新的拖动不再产生这类会改变骨长的数据。

所有调整都作用于整段动作，是相对动画姿态的固定偏移，不是仅修改当前时间点的关键帧。在某一帧拖好的姿势，到其他帧会叠加在各自的动画姿态上。支持重置当前骨骼、还原版本、另存新版本。动作骨架 GLB 导出包含手指、旋转和位置调整，不包含预览人物。

## 数据与密钥

- 密钥读取项目根目录 `.env.local` 的 `TENCENTCLOUD_SECRET_ID` / `TENCENTCLOUD_SECRET_KEY`，可选 `TENCENTCLOUD_REGION`。只在服务端使用，不返回浏览器。
- 本地动作库：`data/motion-workbench/library.json`。
- 不变的原始素材：`data/motion-workbench/assets/<版本 ID>.fbx`。
- 数据沿用项目 `data/` 的 Git 忽略规则。备份时复制整个 `data/motion-workbench/`。
- 关闭工具后，任务编号仍保留；下次启动继续查询。查询或下载失败的版本可点击 **重新查询结果**，不会重新生成。提交阶段被中断且没拿到任务编号时，先在腾讯云核查，避免重复收费。
- 服务仅监听本机 `127.0.0.1:5680`，拒绝跨站调用。没有生产托管接口；请使用 `npm run motion` 运行。

## 导出语义

任意预览角色均可导出当前调整。导出从独立的原始动作骨架副本烘焙，不包含预览人物，也不改变正在预览的姿态、镜头或已保存版本。

GLB 以 30fps 采样并烘焙裁剪、播放速度、骨骼偏移和根位移校正，保留源蒙皮（源 FBX 若有）。源单位按照 HY-Motion 的厘米转换为米。水平锁定以裁剪后第一帧胯部为基准；地面校正以裁剪段采样中的最低脚关节为基准。循环是播放器/编辑记录设置，不承诺自动生成无缝首尾。

任意 FBX 可导入，但姿态编辑和 VRM 预览针对 HY-Motion 的 SMPL-H 命名。其他骨架可预览，骨骼偏移和单位可能需要额外适配。

```sh
npm run motion:check
```
